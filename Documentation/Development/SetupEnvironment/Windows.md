## Windows Developer Environment Setup

### Pull Submodules

`git submodule update --init --recursive`

### Download and Install:

- Visual Studio Community 2022 (with C++ support)
- [CMake](https://cmake.org/download/) 
- Vulkan SDK version 1.3.275.0 (During install select "Shader Toolchain Debug Symbols - 64 bit" and deselect all other options)
- devkitPro (base installer; the GameCube/Wii/3DS toolchains are installed via pacman in the next section)
- Instructions for installing devkitPro can be found in the devkitPro wiki [here](https://devkitpro.org/wiki/Getting_Started)

### Install devkitPro toolchains:

Open your Start Menu and launch `devkitPro > MSys2`, then run each command below separately.

Trust the libogc2 package signing key:

```bash
pacman-key --recv-keys C8A2759C315CFBC3429CC2E422B803BA8AA3D7CE --keyserver keyserver.ubuntu.com
```

```bash
pacman-key --lsign-key C8A2759C315CFBC3429CC2E422B803BA8AA3D7CE
```

Next, edit `C:\devkitPro\msys2\etc\pacman.conf` and add the following entry above the existing `[dkp-libs]` entry. This is **file content, not commands** — the two `Server` lines are mirrors of the same repository (pacman falls back to the second if the first is unreachable), and both lines belong in the file:

```ini
[libogc2-devkitpro]
Server = https://packages.libogc2.org/devkitpro/windows/$arch
Server = https://packages.extremscorner.org/devkitpro/windows/$arch
```

Back in the MSys2 shell, sync and update:

```bash
pacman -Syuu
```

Then install the toolchains and libraries (accept overwriting if asked):

```bash
pacman -S wii-dev 3ds-dev gamecube-tools-git libogc2 libogc2-libdvm
```

> Note: the `libogc2` packages are only the GameCube/Wii **libraries**. `wii-dev` and `3ds-dev` are the meta-packages that pull in the actual compilers — devkitPPC (`powerpc-eabi-g++`) and devkitARM (`arm-none-eabi-g++`). Without them, shader compilation and the editor will work, but GameCube/Wii/3DS packaging will fail partway through `make` with a missing-compiler error.

Verify the setup in the MSys2 shell. First check the environment variables the build reads — the Makefiles fail immediately if these are missing from the environment `make` runs in:

```bash
echo $DEVKITPRO
echo $DEVKITPPC
echo $DEVKITARM
```

Expect output like `/opt/devkitpro` and `/opt/devkitpro/devkitPPC` (MSYS-style; Windows-style values like `C:\devkitPro\devkitPPC` also work — either way it must point at the toolchain root folder, **not** a `\bin` subfolder). If any prints empty, the devkitPro installer's environment setup didn't take — restart your computer, and if it's still empty, re-run the devkitPro installer.

Then verify the compilers by full path (both should print a version):

```bash
/opt/devkitpro/devkitPPC/bin/powerpc-eabi-g++ --version
```

```bash
/opt/devkitpro/devkitARM/bin/arm-none-eabi-g++ --version
```

> Note: the compiler `bin` folders are deliberately **not** on the shell PATH — the build invokes compilers via `$(DEVKITPPC)/bin/`. A bare `powerpc-eabi-g++` printing "command not found" does *not* mean the install is broken; always test with the full paths above.

- Restart computer if you've opened Visual Studio prior to installing the toolchains to make sure the environment variables (`DEVKITPRO`, `DEVKITPPC`, `DEVKITARM`) are found.
- Build shaders, `libgit2`, and the `Standalone\Generated\` embedded-asset stubs by running `Tools\prebuild.bat`. The stub step writes minimal placeholders for `EmbeddedAssets.{h,cpp}`, `EmbeddedScripts.{h,cpp}`, and `AddonPlugins.cpp` only if they are missing — these files are gitignored and normally regenerated by the Editor's "Build Data" action, but a fresh clone needs the stubs so `Standalone` compiles. (Requires Python 3 on PATH.)

### Visual Studio Setup & Editor Build

1. Open ``Polyphase.sln`` .
2. Switch to the ``DebugEditor`` solution configuration.
3. Set the ``Standalone`` project as the Startup Project.
4. In the debug settings for ``Standalone``, change the working directory to ``$(SolutionDir)``.
5. Build and run ``Standalone``. This is the standalone level editor if you were making a game with Lua script only.
